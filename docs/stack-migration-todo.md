# Roadmap внедрения стека (поэтапно)

## Принципы выполнения

- Двигаемся строго по фазам.
- В каждой фазе есть цель, шаги и критерии готовности.
- Следующую фазу начинаем только после проверки предыдущей.

## Фаза 1. TypeScript strict для backend/frontend базы

Цель:

- Зафиксировать единую строгую типизацию и добавить обязательный typecheck.

Шаги:

1. Вынести базовые strict-настройки в общий `tsconfig.base.json`.
2. Подключить backend-конфиг через `extends`.
3. Добавить скрипты `typecheck` для backend и frontend-заготовки.
4. Проверить `npm run typecheck`, `npm run build`, `npm test`.

Критерии готовности:

- Typecheck запускается одной командой.
- Сборка и тесты проходят без регрессий.

## Фаза 2. API-слой на Node.js + Express

Цель:

- Укрепить структуру API-слоя и подготовить место для валидации и middlewares.

Шаги:

1. Выделить bootstrap приложения и конфигурацию сервера.
2. Унифицировать формат API-ошибок.
3. Подготовить middleware-цепочку под валидацию запросов.
4. Проверить обратную совместимость endpoint.

Критерии готовности:

- API-слой разделен по зонам ответственности.
- Существующие endpoint работают как раньше.

## Фаза 3. gRPC client слой (`@grpc/grpc-js`, `@grpc/proto-loader`)

Цель:

- Сохранить gRPC как источник данных, усилить типизацию и надежность.

Шаги:

1. Привести gRPC-адаптеры к более типизированному виду.
2. Доработать retry/timeout/backoff стратегию.
3. Добавить тесты для gRPC-оберток.

Критерии готовности:

- gRPC слой стабилен при временных ошибках.
- Ключевые сценарии покрыты тестами.

## Фаза 4. Zod-валидация payload и нормализация ответов

Цель:

- Валидировать `token`, `accountId` и формализовать контракты API.

Шаги:

1. Добавить Zod-схемы входных payload.
2. Подключить middleware валидации в API.
3. Нормализовать ключевые API-ответы через DTO/схемы.

Критерии готовности:

- Невалидные входные данные корректно отклоняются.
- Ответы API имеют стабильный формат.

## Фаза 5. Frontend на React + Vite

Цель:

- Уйти от inline JS/HTML к компонентному frontend.

Шаги:

1. Инициализировать `web` пакет на React+Vite+TS.
2. Перенести каркас страниц и общие UI-блоки.
3. Подключить frontend к существующим API.

Критерии готовности:

- React-приложение запускается и получает данные из API.
- Основные экраны перенесены.

## Cutover стратегия

1. Параллельный режим:
   `legacy` UI продолжает работать на серверных страницах из `src/ui/*`, новый UI развивается в `web/`.
2. Приемка:
   обязательные проверки `npm run typecheck`, `npm run build`, `npm run web:build`, `npm run test:vitest`, `npm run test:e2e`.
3. Переключение:
   Express начинает отдавать `web/dist` как основной frontend.
4. Страховка:
   legacy UI доступен под feature flag на период стабилизации.
5. Завершение:
   после стабилизации и мониторинга метрик удаляются legacy-страницы.

## Релизный чеклист

1. Все тестовые контуры проходят локально.
2. `/api/metrics` и `/metrics` отдают валидные данные.
3. Smoke e2e проходит на чистом окружении.
4. README содержит актуальные команды.
5. Cutover шаги проверены на staging.
